01 What this file does

purple_plotter.py is a pure Python command-line script that accepts file paths as CLI arguments, reads PURPLE copy-number and B-allele-frequency outputs together with optional CNVkit files, converts all the tabular data into BEDGraph and SEG format strings, then fills a single HTML template to produce a fully self-contained IGV.js copy-number viewer. The file has no DNAnexus API calls and makes no network requests at runtime — it is plain Python plus pandas, invoked by the DNAnexus app's bash wrapper after it has downloaded all the inputs. The output is a single .igv.bars.html file whose entire data payload is embedded as JavaScript template literals; opening it in a browser requires only access to the CDN-hosted igv.js library script tag already included in the template.

What it is NOT

This file contains no dxpy API calls, no network I/O, and no subprocess invocations. It is a pure data-transformation script. The DNAnexus plumbing — downloading inputs, setting environment variables, and uploading the finished HTML — is handled entirely by a separate bash entry-point script that calls this Python file once all files are in place.

02 The four phases

Every run of purple_plotter.py passes through four sequential phases: CLI argument ingestion, data loading from files on disk, conversion of DataFrames to text-format strings, and HTML rendering. The diagram below shows how they connect; data flows strictly left to right with no feedback loops.

Phase Entry point Inputs Outputs
Ingest main() via argparse Command-line argument strings (file paths, sample ID, locus) Populated argparse.Namespace; Path objects passed to loaders
Load load_purple_data(), load_qc_data(), load_msi_data(), load_cnvkit_data() Path objects (files on disk); None for optional absent files PurpleData, QCData, MSIData, CNVkitData dataclass instances holding DataFrames and scalars
Convert 9 conversion functions — e.g. cn_bars_by_state(), baf_bedgraph(), to_seg() Pandas DataFrames + ploidy float from QCData BEDGraph strings, SEG strings, dicts of per-state BEDGraph strings
Render render_html() → write_html() All converted strings + PlotInputs metadata Complete HTML string written to {sample_id}.igv.bars.html on disk

04 External dependencies

The file imports from two sources: Python's standard library and the single third-party package pandas. No other packages are required — not even dxpy, since this script is deliberately kept as a standalone tool that the DNAnexus bash wrapper calls after downloading all inputs.

Standard library

Module How it is used in this file
argparse Defines and parses the nine CLI flags (--sample, --purple_tar, --locus, etc.) inside main(); also provides the ap.error() call that enforces the constraint that at least one of --purple_tar or --cnvkit_cnr must be present
gzip gzip.decompress(bytes) unpacks the AMBER BAF file which is gzip-compressed a second time inside the PURPLE tar archive (production archives use .amber.baf.tsv.gz, creating a double-compressed member)
html (as _html) _html.escape() sanitises user-supplied strings — sample ID, QC status, MSI score — before they are written into the HTML and JavaScript sections of the output template

math math.log2() computes the log₂ ratio used in every copy-number conversion function; math.isfinite() guards against NaN and ∞ values in CNVkit data which has -inf for zero-coverage bins
tarfile tarfile.open(path, "r:gz") opens and inspects the PURPLE .tar.gz archive; tf.getmembers() lists contents; tf.extractfile(member).read() extracts individual files as bytes
dataclasses Provides the @dataclass decorator and the field() helper; used in all five data-model classes to auto-generate constructors and to safely define mutable default values
pathlib Path objects are used throughout for file path construction, .exists() checks, .write_text() for output, and .mkdir(parents=True) to create the output directory

Name Lines (approx.) Phase One-line purpose

load_qc_data() ~90–100 Load Reads purity, ploidy, and PURPLE QC status from the QC TSV; returns safe defaults if the path is None or the file is absent
load_msi_data() ~103–111 Load Reads msi_score from the MSI TSV, classifies as MSI-H or MSS using the 8.0 threshold, returns defaults if absent
load_cnvkit_data() ~114–126 Load Reads the three optional CNVkit files (.cnr, .call.cns, .genemetrics.csv); stores None in the dataclass for any absent path
coverage_log2_bedgraph() ~131–141 Convert Converts PURPLE target-region CN data to log₂(windowTumorRatio) BEDGraph; skips masked windows and windows with ratio ≤ 0.05
cn_bars_by_state() ~144–157 Convert Converts segments to log₂(CN/ploidy) BEDGraph partitioned into 5 state-keyed strings (hodel / loss / diploid / gain / amp) by threshold
baf_bedgraph() ~160–170 Convert AMBER BAF scatter top arm: tumorBAF − 0.5 per site; converts 1-based AMBER position to 0-based BEDGraph interval (pos−1, pos)
baf_bedgraph_mirror() ~173–182 Convert BAF scatter bottom arm: 0.5 − tumorBAF per site; mirror of baf_bedgraph() to show the symmetric lower allele arm
baf_seg_bars_by_state() ~185–206 Convert Fitted BAF segment bars from the segment TSV, split by CN state and mirrored top/bottom; returns a 10-key dict (5 states × 2 arms)
to_seg() ~209–222 Convert Converts PURPLE segment.tsv to an IGV SEG string; one tab-separated row per segment with log₂(CN/ploidy) as Seg_Mean
cnr_to_bedgraph() ~225–234 Convert CNVkit .cnr per-target log₂ ratios to BEDGraph; skips any non-finite (NaN / ∞) values
cns_to_seg() ~237–253 Convert CNVkit .call.cns to IGV SEG string; uses integer cn column when available, falls back to raw log2 ratio when absent
genemetrics_to_bedgraph() ~256–265 Convert CNVkit .genemetrics.csv to BEDGraph of gene-level log₂ values; skips non-finite values
HTML_BARS (constant) ~270–400 — Module-level string constant: the ~130-line igv.js HTML template with {placeholder} format slots for all 19 data strings and 7 metadata values
render_html() ~405–455 Render Calls all conversion functions, sanitises strings for HTML / JS contexts, fills HTML_BARS.format(**kwargs) with 26 named keyword arguments
write_html() ~458–464 Render Calls render_html(), creates the output directory if needed, writes the HTML string to {sample_id}.igv.bars.html
main() ~469–510 CLI Entry point: parses CLI arguments, calls all four loaders, assembles the PlotInputs dataclass, calls write_html(), prints the output path

06 Naming conventions & how to use this series

The file uses a small set of consistent suffixes and prefixes throughout. Learning them makes the code predictable to read: given any variable name you can immediately know what it holds.

  • Everything is snake_case — all functions, variables, parameters, and module-level names follow PEP 8 snake_case without exception.
  • *_df suffix marks DataFrames — every pandas.DataFrame is named with a _df ending: baf_df, cn_df, seg_df, cnr_df, cns_df, gm_df. Short-lived filtered subsets use sub.
  • *_bg suffix marks BEDGraph strings — all variables that hold a BEDGraph-format string end in _bg: cov_log2_bg, baf_bg, baf_mir_bg, cnvkit_cnr_bg. Dicts of per-state strings use the plural *_bgs: bar_bgs, baf_bar_bgs.
  • Data suffix on dataclass class names — PurpleData, QCData, MSIData, CNVkitData all carry the Data suffix. The top-level aggregator is PlotInputs (it holds inputs, not a single data domain).
  • Inner helper function prefix — locally-scoped helper functions defined inside a loader use a leading underscore (_read in load_cnvkit_data) or a descriptive name (read_by_suffix in load_purple_data).
  • load_ prefix on all data-loading functions — the four top-level loaders all begin with load_, making them trivially distinguishable from the nine conversion functions and two render functions.
