19 load_purple_data

This function handles two non-obvious challenges: reading files out of a compressed archive without writing to disk, and dealing with the double-compression of the BAF file. The numbered markers below highlight the most important lines.

load_purple_data(purple_tar, sample_id) Extract three DataFrames from a PURPLE tar.gz archive 
def load_purple_data(purple_tar: Path, sample_id: str) -> PurpleData:
    """Extract amber.baf.tsv, target_region_cn.tsv, purple.segment.tsv from tar.gz."""
    with tarfile.open(purple_tar, "r:gz") as tf:  # ①
        members = tf.getmembers()                  # ②

        def read_by_suffix(suffix: str) -> pd.DataFrame:  # ③
            member = next(                                  # ④
                (m for m in members if m.name.endswith(suffix)), None
            )
            if member is None:
                raise RuntimeError(
                    f"Could not find *{suffix} in {Path(purple_tar).name}"
                )
            return pd.read_csv(                            # ⑤
                io.BytesIO(tf.extractfile(member).read()), sep="\t"
            )

        baf_gz_member = next(                              # ⑥
            (m for m in members if m.name.endswith(".amber.baf.tsv.gz")), None
        )
        if baf_gz_member is not None:
            raw    = gzip.decompress(                      # ⑦
                tf.extractfile(baf_gz_member).read()
            )
            baf_df = pd.read_csv(io.BytesIO(raw), sep="\t")  # ⑧
        else:
            baf_df = read_by_suffix("amber.baf.tsv")

        return PurpleData(
            baf_df = baf_df,
            cn_df  = read_by_suffix("target_region_cn.tsv"),
            seg_df = read_by_suffix("purple.segment.tsv"),
        )
①
"r:gz" opens a gzip-compressed tar for reading. The with block keeps the archive open for all member reads, then closes (and releases the file handle) automatically on exit — even if an exception is raised mid-function.
②
Snapshot the member list once. getmembers() returns a list of all archive entries. Calling it once and reusing the list is cheaper than rescanning the archive for every lookup — and is necessary because the archive file object does not support random seeks.
③
Inner closure captures tf and members from the enclosing scope. This is a nested function (closure): it can read tf and members without them being passed as arguments. It exists only inside load_purple_data, keeping the shared extraction logic in one place without exposing it as a module-level helper.
④
Generator + next(…, None) finds the first matching member or returns None. The generator expression scans lazily, stopping at the first match. The None default means a missing member produces a clean RuntimeError on the next line rather than a cryptic AttributeError from trying to call extractfile(None).
⑤
In-memory extraction with BytesIO. tf.extractfile(member) returns a file-like object; .read() loads all bytes; io.BytesIO(…) wraps them in an object that satisfies pandas' file-reading interface. No temporary file is written to disk — important in a Docker container with a small /tmp partition.
⑥
Probe for the double-compressed BAF member before trying the plain fallback. In production, PURPLE tars contain .amber.baf.tsv.gz; test fixtures use plain .amber.baf.tsv. Probing separately avoids a try/except and makes the two code paths explicit and independently readable.
⑦
Double compression: gzip.decompress handles the inner gzip layer. The tar file itself is gzip-compressed (handled by "r:gz" in the open call). This specific member is also gzip-compressed. tarfile strips the outer layer; gzip.decompress strips the inner one. Without this call, pandas would receive raw gzip bytes and fail to parse them as TSV.
⑧
Same BytesIO pattern after decompression. After gzip.decompress the result is raw bytes (not a file-like object), so io.BytesIO wraps them into the interface pandas expects. This is identical in structure to the read_by_suffix return — consistency makes both paths easy to audit together.

20 cn_bars_by_state

This function contains the core CN-state bucketing algorithm used by every bar-chart track in the viewer. Understanding it fully makes baf_seg_bars_by_state (which follows the same pattern) straightforward.

cn_bars_by_state(seg_df, ploidy) Distribute PURPLE segments into five CN-state BEDGraph buckets 
def cn_bars_by_state(seg_df: pd.DataFrame, ploidy: float) -> dict[str, str]:
    """log2(CN/ploidy) per segment split by CN state — one interval per segment."""
    denom   = max(ploidy, 0.1)                                  # ①
    buckets = {key: [] for key, *_ in CN_STATES}                # ②
    for chrom in CHR_ORDER:                                     # ③
        for _, row in seg_df[                                   # ④
            seg_df["chromosome"] == chrom
        ].iterrows():
            cn = float(row.get("tumorCopyNumber", 0))           # ⑤
            if cn <= 0:                                         # ⑥
                continue
            log2_r = math.log2(cn / denom)
            start, end = int(row["start"]), int(row["end"])
            for key, lo, hi, _ in CN_STATES:                   # ⑦
                if lo <= log2_r < hi:
                    buckets[key].append(
                        f"{chrom}\t{start}\t{end}\t{log2_r:.4f}"
                    )
                    break                                        # ⑧
    return {k: "\n".join(v) for k, v in buckets.items()}        # ⑨
①
Floor the denominator to prevent division-by-zero. If ploidy is 0 or negative (which PURPLE should never produce but technically could), dividing by it would raise a ZeroDivisionError or produce -inf. The floor value of 0.1 is far enough from zero to produce meaningful log2 values without affecting any realistic ploidy estimate.
②
Dict comprehension over CN_STATES; *_ discards unneeded tuple fields. Each tuple in CN_STATES has four elements: (key, lo, hi, colour). The *_ unpacking captures and discards the last three, leaving only key. Each bucket starts as an empty list that accumulates BEDGraph line strings before being joined at the end.
③
Outer loop over CHR_ORDER enforces chromosome sort order. BEDGraph files are expected to be chromosome-sorted; igv.js may fail to index tracks that are not ordered. Processing chromosomes in the canonical order (chr1–chr22, chrX) guarantees sorted output regardless of how the input DataFrame is ordered.
④
Filter DataFrame before iterating rows. Filtering to the current chromosome before calling iterrows() reduces the number of Python-level iterations. _ discards the pandas integer row index (which is not meaningful here); row is a pd.Series with column names as keys.
⑤
row.get() with default 0 handles missing columns gracefully. On a pd.Series, .get(key, default) returns the default if the column is absent — useful if a variant of the TSV format omits the CN column. The explicit float() call normalises values that pandas may have read as strings (in mixed-type columns) or as integer 0 (the default).
⑥
Skip rather than clamp CN ≤ 0. PURPLE uses CN=0 for truly uncallable regions where no copy-number estimate is possible. Clamping to a small positive value would create spurious bars in the homdel track. Skipping means the segment contributes nothing — an honest representation of "no data".
⑦
Linear scan of CN_STATES uses half-open intervals [lo, hi). The five states cover the entire real line: hodel (−∞ to −1.0), loss (−1.0 to −0.3), diploid (−0.3 to 0.3), gain (0.3 to 1.0), amp (1.0 to +∞). The final state has hi=1e9 acting as a practical infinity. Half-open intervals mean no value falls into a gap between states.
⑧
break after appending prevents double-counting at boundaries. Without break, a value of exactly 0.3 (gain lower bound) would match both the diploid interval (0.3 is the diploid upper bound) and the gain interval. The half-open definition [lo, hi) already handles this mathematically, but the break exits the loop immediately as a safety measure and a performance micro-optimisation.
⑨
Join lists into strings; empty buckets produce empty strings. A bucket with no segments produces "" when joined. In render_html, this becomes blob("") — a blob URL pointing to zero bytes — which igv.js accepts as an empty track. This is why a sample with no amplifications still renders correctly: the amp track is present but empty.

21 baf_seg_bars_by_state

This function adapts the bucketing algorithm from cn_bars_by_state to produce a mirrored butterfly plot for the fitted BAF track. The key insight is that the CN state determines the colour of each bar, while the BAF value determines the height — these are independent axes.

baf_seg_bars_by_state(seg_df, ploidy) Fitted BAF bars coloured by CN state, mirrored top and bottom arms (10-key dict) 
def baf_seg_bars_by_state(seg_df: pd.DataFrame, ploidy: float) -> dict[str, str]:
    """Fitted BAF bar chart split by CN state, mirrored top + bottom arms."""
    denom   = max(ploidy, 0.1)
    buckets = {                                                 # ①
        f"{k}_{arm}": []
        for k, *_ in CN_STATES
        for arm in ("top", "bot")
    }
    for chrom in CHR_ORDER:
        sub = seg_df[                                          # ②
            (seg_df["chromosome"] == chrom)
            & (seg_df["tumorCopyNumber"] > 0)
            & (seg_df["tumorBAF"] > 0)
        ]
        for _, row in sub.iterrows():
            cn    = float(row["tumorCopyNumber"])
            baf   = min(1.0, max(0.0, float(row["tumorBAF"])))  # ③
            start, end = int(row["start"]), int(row["end"])
            log2_r    = math.log2(cn / denom)                   # ④
            state_key = CN_STATES[-1][0]                        # ⑤
            for key, lo, hi, _ in CN_STATES:
                if lo <= log2_r < hi:
                    state_key = key
                    break
            buckets[f"{state_key}_top"].append(                 # ⑥
                f"{chrom}\t{start}\t{end}\t{baf - 0.5:.4f}"
            )
            buckets[f"{state_key}_bot"].append(                 # ⑦
                f"{chrom}\t{start}\t{end}\t{0.5 - baf:.4f}"
            )
    return {k: "\n".join(v) for k, v in buckets.items()}
①
Nested comprehension creates 10 keys. Iterating over CN_STATES (5 states) and ("top", "bot") (2 arms) produces: hodel_top, hodel_bot, loss_top, loss_bot, diploid_top, diploid_bot, gain_top, gain_bot, amp_top, amp_bot. render_html only uses 8 of these (diploid top/bot are computed but not placed in the template — diploid BAF bars at y≈0 are visually invisible and omitted by design).
②
Combined boolean filter excludes uninformative segments in one step. Segments with tumorCopyNumber ≤ 0 are excluded because log2(0) is undefined. Segments with tumorBAF ≤ 0 are excluded because BAF=0 cannot represent a heterozygous site — it typically marks a region where AMBER found no informative SNPs. Note the pandas & operator (not Python's and) is required for element-wise boolean operations on Series.
③
min(1.0, max(0.0, baf)) clamps BAF to a valid range before arithmetic. PURPLE's fitting optimiser minimises a continuous likelihood function and can occasionally produce a BAF marginally outside [0, 1] due to floating-point precision. Without clamping, baf - 0.5 could exceed 0.5 (top bar extending past the track boundary) or 0.5 - baf could go negative (bottom bar pointing upward). Either would produce visually confusing output in igv.js.
④
log2 is computed for colour determination only, not for bar height. The y-axis position of each bar is entirely driven by the BAF value. The log2(CN/ploidy) value is used only to look up which CN-state colour bucket the segment belongs to. This separates the two visual channels: colour encodes copy-number state; height encodes allelic balance.
⑤
Default state_key to the last state before the scan. CN_STATES[-1][0] is "amp". Setting it as the default before the loop means the variable is always assigned even if the loop completes without a break — which can happen if log2_r is exactly at the amp lower bound (1.0) and floating-point comparison resolves unexpectedly. This is a defensive default rather than a real edge case.
⑥
Top arm: positive value extends the bar upward from y=0. For a segment with BAF=0.72 (mild LOH), baf - 0.5 = 0.22 — the bar extends 0.22 units above the baseline. For a balanced segment (BAF=0.5), baf - 0.5 = 0.0 — the bar is a zero-height point, invisible in the track.
⑦
Bottom arm: mirror image at 0.5 - baf extends downward. For BAF=0.72, 0.5 - 0.72 = -0.22 — the bar extends 0.22 units below the baseline. Together the top and bottom bars for the same segment are symmetric about y=0, creating the characteristic butterfly pattern that makes LOH visually obvious in a genome-wide view.

22 render_html

This is the orchestrator function. The most important non-obvious lines involve the three different escaping strategies applied to the same sample ID string before it is injected into three different syntactic contexts in the HTML/JavaScript template.

render_html(inputs) Calls all conversion functions and fills the HTML_BARS template; annotated excerpt shown 
def render_html(inputs: "PlotInputs") -> str:
    """Fill HTML_BARS template from PlotInputs. Empty strings → empty blob URLs."""
    ploidy = inputs.qc.ploidy

    sample_js = (                                              # ①
        inputs.sample_id
        .replace("`", "\\`")
        .replace("${", "\\${")
    )

    if inputs.purple is not None:                              # ②
        cov_log2_bg = coverage_log2_bedgraph(inputs.purple.cn_df)
        bar_bgs     = cn_bars_by_state(inputs.purple.seg_df, ploidy)
        baf_bg      = baf_bedgraph(inputs.purple.baf_df)
        baf_mir_bg  = baf_bedgraph_mirror(inputs.purple.baf_df)
        baf_bar_bgs = baf_seg_bars_by_state(inputs.purple.seg_df, ploidy)
        seg_data    = to_seg(inputs.purple.seg_df, sample_js, ploidy)
    else:
        cov_log2_bg = ""
        bar_bgs     = {k: "" for k, *_ in CN_STATES}          # ③
        baf_bg = baf_mir_bg = seg_data = ""
        baf_bar_bgs = {
            f"{k}_{arm}": ""
            for k, *_ in CN_STATES for arm in ("top", "bot")
        }
    ...
    purity_str = (                                             # ④
        "?" if not inputs.qc.loaded
        else f"{inputs.qc.purity:.0%}"
    )
    ploidy_str = (
        "?" if not inputs.qc.loaded
        else f"{inputs.qc.ploidy:.2f}"
    )
    sample_html = _html.escape(inputs.sample_id)              # ⑤
    locus_js    = (                                           # ⑥
        inputs.locus
        .replace("\\", "\\\\")
        .replace('"', '\\"')
    )
    return HTML_BARS.format(
        sample=sample_html, purity=purity_str, ploidy=ploidy_str,
        ...  # 20+ further named kwargs
    )
①
sample_js — escaping for JavaScript backtick template literals. In the HTML template, sample_id lands inside JS strings delimited by backticks: const segData = `...{sample}_cnvkit...`. A literal backtick in the sample ID would prematurely end the JS string. A ${ sequence would trigger JS template interpolation and produce a ReferenceError. Both are escaped by prepending a backslash, which JavaScript's backtick strings treat as a literal character.
②
The entire PURPLE conversion block is guarded by inputs.purple is not None. If no --purple_tar was supplied, every PURPLE-derived variable is set to an empty string instead of being computed. This is the "empty-string degradation" design: the template format call below receives identically-named arguments regardless of whether PURPLE data is present, so the template itself has no conditional logic.
③
The else branch creates the same dict structure as the real converters, but all-empty. cn_bars_by_state returns {"hodel": "...", "loss": "...", ...}. The else branch produces {"hodel": "", "loss": "", ...}. Downstream code accesses bar_bgs["amp"], bar_bgs["gain"] etc. identically in both cases — no special-casing required.
④
purity_str uses the loaded flag, not the status string. A QC file can have status="UNKNOWN" (valid PURPLE output for samples where the purity fitting was inconclusive) — but it was still successfully read, so loaded=True. Using loaded correctly shows real numeric purity and ploidy for UNKNOWN-status samples. If the file was absent, loaded=False and both fields show "?".
⑤
sample_html — escaping for HTML element content and attributes. _html.escape() converts <, >, &, and " to their HTML entity equivalents. This prevents sample IDs containing angle brackets or ampersands from breaking the HTML structure. A separate variable is needed because HTML escaping rules differ from JavaScript escaping rules — the same escaping cannot be used for both contexts.
⑥
locus_js — escaping for a JavaScript double-quoted string. In the template, locus lands inside: locus: "{locus}". A " in the locus string would close the JS string early. Backslashes must be escaped first (before double-quotes) to avoid double-escaping: if a locus were chr1:1-2", processing double-quotes first then backslashes would incorrectly escape the newly-inserted backslash.

23 cns_to_seg

This function is subtler than it appears. The two-branch CN logic exists because CNVkit explicitly represents homdels as cn=0 — which is a valid and clinically important call — whereas PURPLE's converter skips CN=0 entirely. Getting this right requires a specific numeric floor rather than a simple skip.

cns_to_seg(cns_df, sample, ploidy) CNVkit .call.cns to IGV SEG; two-branch logic for integer cn vs raw log2 
def cns_to_seg(cns_df: pd.DataFrame, sample: str, ploidy: float) -> str:
    """CNVkit .call.cns → IGV SEG (log2(CN/ploidy), or raw log2 if cn absent)."""
    denom = max(ploidy, 0.1)
    lines = [                                                   # ①
        "SampleID\tChromosome\tStart\tEnd\tNum_Probes\tSeg_Mean"
    ]
    for chrom in CHR_ORDER:
        for _, row in cns_df[cns_df["chromosome"] == chrom].iterrows():
            cn = float(row.get("cn", -1))                      # ②
            if cn >= 0:
                seg_mean = math.log2(max(cn, 0.01) / denom)    # ③
            else:
                raw = float(row.get("log2", float("nan")))     # ④
                if not math.isfinite(raw):                     # ⑤
                    continue
                seg_mean = raw
            lines.append(
                f"{sample}_cnvkit"                             # ⑥
                f"\t{chrom}\t{int(row['start'])}\t{int(row['end'])}"
                f"\t{int(row.get('probes', 0))}\t{seg_mean:.4f}"
            )
    return "\n".join(lines)
①
The SEG header line is required by the format specification. igv.js uses the exact column names SampleID, Chromosome, Start, End, Num_Probes, Seg_Mean to identify the file as SEG format and to determine which column to use for colouring. An absent or differently-named header causes igv.js to misparse or refuse the file silently.
②
row.get("cn", -1) uses −1 as a sentinel for "absent or uncalled". CNVkit .call.cns files always have a cn column, but it may contain −1 for segments where the caller could not assign an integer copy number. The -1 sentinel ensures the else-branch (raw log2 fallback) is taken for these rows; using None would not work because float(None) raises a TypeError.
③
max(cn, 0.01) floors copy number to 0.01 to preserve homdel calls. When CNVkit calls a true homozygous deletion, it sets cn=0. Without the floor, math.log2(0) would raise a ValueError. With the floor: log2(0.01 / 2.0) ≈ −7.6 — a strongly negative value that renders as a deep red bar in igv.js, which is the correct visual signal for a homdel. By contrast, the PURPLE converter (to_seg) skips CN=0 because PURPLE marks truly uncallable regions as CN=0, not confirmed homdels.
④
Fallback to the raw log2 column when cn is absent or −1. Older CNVkit output files or CNVkit runs without the call step may lack integer CN calls entirely. The raw log2 ratio is a valid track value for igv.js — it just will not be normalised to ploidy because ploidy information was not applied during the CNVkit call step.
⑤
math.isfinite(raw) skips rows with NaN or ±Inf log2 values. CNVkit emits NaN at chromosome ends and centromeres where read depth cannot be estimated, and ±Inf at windows with zero reference depth. These are not errors — they are honest "no data" signals. Skipping rather than clamping means igv.js receives no bar for those regions, which is visually correct.
⑥
The _cnvkit suffix distinguishes CNVkit segments from PURPLE segments in igv.js. Both PURPLE and CNVkit segments are loaded as separate const variables in the template and fed to separate igv.js tracks. If both used the same sample ID in their SEG data, igv.js would merge them into a single row in the seg track display, making it impossible to visually distinguish the two callers.
