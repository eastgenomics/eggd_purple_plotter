15 Data loading functions

Four load_* functions each own the job of reading one external file type. They all return typed dataclasses, and all degrade gracefully — returning a default dataclass when a path is absent. This means render_html never needs to check for None on QC, MSI, or CNVkit fields; only the PURPLE data is explicitly optional because the whole module can run without it.

load_purple_data(purple_tar, sample_id) lines 63–90 Load

Opens a PURPLE .tar.gz archive and extracts three TSV dataframes: AMBER BAF values, target-region copy-number windows, and PURPLE segments.

Inputs

  • purple_tar — Path to the PURPLE .tar.gz archive
  • sample_id — Sample identifier (available for error messages; not used in extraction logic)

Output

  • PurpleData dataclass with three DataFrames: baf_df, cn_df, seg_df

The archive is opened with tarfile.open(…, "r:gz") inside a with block. An inner closure read_by_suffix locates a member by filename suffix, extracts its bytes via tf.extractfile(member).read(), wraps them in a BytesIO object, and returns a pandas DataFrame — no temporary files are written to disk.

The BAF file uses a dual-format probe. In production PURPLE tars the .amber.baf.tsv is itself gzip-compressed, producing double compression: the tar is gzip-compressed, and this member is also gzip-compressed inside it. The function probes for the .amber.baf.tsv.gz member first; if found, gzip.decompress() handles the inner layer. If absent, the plain .amber.baf.tsv fallback is used.

# Probe for production double-compressed member first
baf_gz_member = next(
    (m for m in members if m.name.endswith(".amber.baf.tsv.gz")), None
)
if baf_gz_member is not None:
    raw    = gzip.decompress(tf.extractfile(baf_gz_member).read())
    baf_df = pd.read_csv(io.BytesIO(raw), sep="\t")
else:
    baf_df = read_by_suffix("amber.baf.tsv")  # test-fixture fallback
Design decision — BAF fallback

The plain-.tsv fallback branch exists purely for local testing with lightweight fixtures. Production PURPLE archives always contain the gzip-compressed member. Keeping both paths in the same function means unit tests run the same code path as production — only the inner decompression layer differs.

load_qc_data(qc_report) lines 93–102 Load

Parses purity, ploidy, and QC status from a single-row TSV. Returns QCData() with loaded=False if the path is None or the file does not exist.

Inputs

  • qc_report — Path or None

Output

  • QCData(purity, ploidy, status, loaded)

The status cell is tested with pd.isna() rather than a string comparison against "nan". Pandas reads blank TSV cells as float("nan") — a string comparison would silently fail. The loaded flag is set to True only on a successful read; render_html uses this flag (not the status value) to decide whether to show "?" for purity and ploidy. A QC file with status="UNKNOWN" — valid PURPLE output for borderline samples — still has loaded=True and shows real numeric values.

load_msi_data(msi_report) lines 105–113 Load

Reads an MSI score from a TSV and classifies the sample as MSI-H or MSS by applying the constant MSI_THRESHOLD = 8.0. Returns MSIData("?", "?") if the path is None or absent.

Inputs

  • msi_report — Path or None

Output

  • MSIData(score_str, status_str) — e.g. ("12.40%", "MSI-H")

Both output strings are pre-formatted for direct injection into the HTML header bar, keeping render_html free of any MSI formatting logic. The "?" defaults ensure graceful rendering when the MSI report is not supplied.

load_cnvkit_data(cnr, call_cns, genemetrics) lines 116–127 Load

Loads up to three optional CNVkit output files. Any absent or None path yields a None DataFrame in the returned dataclass.

Inputs

  • cnr — Path to .cnr or None
  • call_cns — Path to .call.cns or None
  • genemetrics — Path to genemetrics CSV or None

Output

  • CNVkitData(cnr_df, cns_df, gm_df) — any field may be None

The inner helper _read(p) consolidates the existence check and TSV read into a single line, removing boilerplate from three identical paths. Because any combination of absent inputs is valid, a caller supplying only --cnvkit_cnr receives a CNVkitData with two None fields — the downstream conversion functions each guard against None before calling their converter.

16 Coverage and CN conversion functions

These two functions convert PURPLE's per-window and per-segment copy-number data into BEDGraph strings. The resulting strings are embedded directly as blob URLs in the igv.js configuration — an empty string produces an empty track, which igv.js renders silently with no errors.

coverage_log2_bedgraph(cn_df) lines 131–142 Convert

Converts per-window tumor copy-number ratios to log2 values and returns a chromosome-sorted BEDGraph string for the IGV coverage scatter track.

Inputs

  • cn_df — target_region_cn.tsv DataFrame; key columns: chromosome, windowStart, windowEnd, masked, windowTumorRatio

Output

  • BEDGraph string — one row per unmasked window where windowTumorRatio > 0.05

Iterates chromosomes in CHR_ORDER (chr1–chr22, chrX), filters to unmasked rows with ratio above the noise threshold, and applies math.log2(ratio). Chromosome-ordered output ensures the BEDGraph is in canonical order for igv.js.

Design decision — 0.05 ratio threshold

Windows with ratio ≤ 0.05 are silently discarded. At this depth, ratios are dominated by sequencing noise and would produce extreme negative log2 values that visually compress the rest of the track. The threshold was chosen empirically to match the noise floor of the coverage display.

cn_bars_by_state(seg_df, ploidy) lines 145–159 Convert

Converts PURPLE segments to log2(CN/ploidy) values and distributes them across five CN-state BEDGraph buckets, returning one BEDGraph string per state.

Inputs

  • seg_df — purple.segment.tsv DataFrame
  • ploidy — float from QC report (default 2.0)

Output

  • dict[str, str] with keys "hodel", "loss", "diploid", "gain", "amp"

denom = max(ploidy, 0.1) prevents division-by-zero for pathological ploidy values. Buckets are initialised as empty lists using a dict comprehension over CN_STATES tuples; the *_ idiom discards the lo/hi/colour fields. Each segment's log2 ratio is tested against five half-open intervals [lo, hi); break exits the inner loop as soon as a match is found to avoid double-counting at boundaries.

denom   = max(ploidy, 0.1)
buckets = {key: [] for key, *_ in CN_STATES}
for chrom in CHR_ORDER:
    for _, row in seg_df[seg_df["chromosome"] == chrom].iterrows():
        cn = float(row.get("tumorCopyNumber", 0))
        if cn <= 0: continue   # skip uncallable regions
        log2_r = math.log2(cn / denom)
        for key, lo, hi, _ in CN_STATES:
            if lo <= log2_r < hi:
                buckets[key].append(f"{chrom}\t{start}\t{end}\t{log2_r:.4f}")
                break
return {k: "\n".join(v) for k, v in buckets.items()}
Design decision — skip CN ≤ 0

Segments with CN ≤ 0 are skipped rather than clamped. PURPLE marks truly uncallable regions as CN=0, and log2(0) is undefined. An empty bucket produces an empty BEDGraph string, which becomes an empty blob URL in the HTML — igv.js renders nothing, which is the correct visual result for a sample with no homdels.

17 BAF conversion functions

Three functions convert AMBER BAF data into BEDGraph strings. baf_bedgraph and baf_bedgraph_mirror together produce the raw-site scatter butterfly plot; baf_seg_bars_by_state produces the fitted-segment bars colored by CN state.

baf_bedgraph(baf_df) lines 162–170 Convert

Converts each AMBER heterozygous site to a top-arm BAF scatter point by computing tumorBAF − 0.5, placing balanced heterozygous sites at y=0 and loss-of-heterozygosity sites near +0.5.

Inputs

  • baf_df — AMBER BAF DataFrame with columns chromosome, position (1-based), tumorBAF

Output

  • BEDGraph string (top arm); values in [−0.5, +0.5]; out-of-range BAF silently skipped

AMBER positions are 1-based, so the BEDGraph coordinate conversion is pos−1, pos to produce 0-based half-open intervals of width 1. Only sites with BAF in [0.0, 1.0] are emitted.

baf_bedgraph_mirror(baf_df) lines 173–181 Convert

Produces the bottom-arm mirror of baf_bedgraph by computing 0.5 − tumorBAF. Together the two functions create a butterfly plot centred on y=0: a balanced heterozygous site contributes a zero-height bar on both arms, while LOH pushes both arms outward symmetrically.

Inputs

  • baf_df — same AMBER BAF DataFrame as baf_bedgraph

Output

  • BEDGraph string (bottom arm); same filtering as baf_bedgraph
baf_seg_bars_by_state(seg_df, ploidy) lines 184–203 Convert

The most complex conversion function: produces fitted BAF segment bars colored by CN state for both top and bottom arms, returning a 10-key dictionary.

Inputs

  • seg_df — PURPLE segment DataFrame (same as cn_bars_by_state)
  • ploidy — float; used only to determine the colour state, not the y-axis height

Output

  • dict[str, str] — 10 keys: hodel_top, hodel_bot, loss_top, loss_bot, diploid_top, diploid_bot, gain_top, gain_bot, amp_top, amp_bot

The bucket dictionary is built with a nested comprehension over CN_STATES and the two arm labels. Each segment's colour is determined by log2(CN/ploidy) using the same CN_STATES thresholds as cn_bars_by_state. The bar height is determined by the fitted BAF: baf−0.5 for the top arm, 0.5−baf for the bottom. These are independent — a diploid segment with LOH has the same bar height as an amplified segment with the same BAF.

# 10 keys: hodel_top/bot, loss_top/bot, diploid_top/bot, gain_top/bot, amp_top/bot
buckets = {f"{k}_{arm}": [] for k, *_ in CN_STATES for arm in ("top", "bot")}
...
baf       = min(1.0, max(0.0, float(row["tumorBAF"])))  # clamp to [0,1]
log2_r    = math.log2(cn / denom)             # for CN-state colour only
state_key = CN_STATES[-1][0]                # default "amp" before scan
for key, lo, hi, _ in CN_STATES:
    if lo <= log2_r < hi:
        state_key = key; break
buckets[f"{state_key}_top"].append(f"{chrom}\t{start}\t{end}\t{baf - 0.5:.4f}")
buckets[f"{state_key}_bot"].append(f"{chrom}\t{start}\t{end}\t{0.5 - baf:.4f}")
Design decision — BAF clamping

min(1.0, max(0.0, baf)) clamps BAF before arithmetic. PURPLE's fitting optimiser can rarely produce a BAF marginally outside [0,1] due to floating-point precision; clamping prevents negative top-arm values or bottom-arm values above 0.5, which would produce visually misleading bars pointing in the wrong direction.

18 SEG, CNVkit, and rendering

The remaining converters produce IGV SEG or BEDGraph strings from PURPLE and CNVkit data. render_html then orchestrates all conversions and fills the HTML template. write_html persists the result, and main is the CLI entry point.

to_seg(seg_df, sample, ploidy) lines 206–219 Convert

Converts PURPLE segment data to IGV SEG format with Seg_Mean = log2(CN/ploidy). Segments with CN ≤ 0 are skipped, consistent with cn_bars_by_state.

Inputs

  • seg_df — PURPLE segment DataFrame
  • sample — JS-escaped sample ID string
  • ploidy — float

Output

  • SEG string with header line SampleID…Seg_Mean; Num_Probes filled with "." (SEG convention for calls without probe counts)
cnr_to_bedgraph(cnr_df) lines 222–232 Convert

Passes per-target CNVkit log2 ratios directly from the .cnr file into a BEDGraph string. No mathematical transformation is applied — math.isfinite() filters out any NaN or ±Inf values that CNVkit emits at low-coverage targets.

Inputs

  • cnr_df — CNVkit .cnr DataFrame with columns chromosome, start, end, log2

Output

  • BEDGraph string; NaN and ±Inf rows omitted
cns_to_seg(cns_df, sample, ploidy) lines 235–252 Convert

Converts CNVkit called segments to IGV SEG format using a two-branch strategy: when the integer cn column is available (≥ 0), computes log2(CN/ploidy); otherwise falls back to the raw log2 ratio from the file.

Inputs

  • cns_df — CNVkit .call.cns DataFrame
  • sample — JS-escaped sample ID
  • ploidy — float; used only in the cn branch

Output

  • SEG string; sample ID suffixed with _cnvkit so PURPLE and CNVkit segments display as separate rows in igv.js
cn = float(row.get("cn", -1))        # -1 sentinel if column absent
if cn >= 0:
    seg_mean = math.log2(max(cn, 0.01) / denom)  # max avoids log2(0)
else:
    raw = float(row.get("log2", float("nan")))
    if not math.isfinite(raw): continue
    seg_mean = raw
Design decision — homdel floor

max(cn, 0.01) floors copy number to 0.01 when cn=0 (true homdel), giving log2(0.01/ploidy) ≈ −7.6 instead of a ValueError. This differs from the PURPLE converter (to_seg) which skips CN=0 entirely — CNVkit explicitly calls homdels as cn=0, so skipping them would silently omit clinically relevant deletions.

genemetrics_to_bedgraph(gm_df) lines 255–263 Convert

The simplest converter: passes per-gene log2 values from CNVkit genemetrics directly to a BEDGraph, skipping any NaN or Inf entries with math.isfinite(). No transformation is applied.

Inputs

  • gm_df — CNVkit genemetrics DataFrame with chromosome, start, end, log2

Output

  • BEDGraph string — one bar per gene, NaN/Inf skipped
render_html(inputs) lines 268–316 Render

The central orchestrator: calls all data-conversion functions, applies context-sensitive escaping to injectable values, and fills the HTML_BARS template with 24+ named keyword arguments to produce the final self-contained HTML string.

Inputs

  • inputs — a fully-populated PlotInputs dataclass

Output

  • Complete HTML string — self-contained IGV bars viewer ready to write to disk

Empty-string degradation: when inputs.purple is None, all PURPLE track variables are set to "" using the same dict structure returned by the real converters. The template still receives every named argument; igv.js receives empty blob URLs and renders empty (but structurally present) tracks, keeping the viewer layout identical whether or not PURPLE data was supplied.

Three escaping contexts: the sample ID appears in three places with different quoting rules, so three separate escaped variants are produced.

# JS backtick literal — escape backtick and ${ interpolation
sample_js   = inputs.sample_id.replace("`", "\\`").replace("${", "\\${")
# HTML context — <title> and <span> elements
sample_html = _html.escape(inputs.sample_id)
# JS double-quoted string — escape backslash then double-quote
locus_js    = inputs.locus.replace("\\", "\\\\").replace('"', '\\"')

QC display: purity_str and ploidy_str show "?" when inputs.qc.loaded is False. A file returning status="UNKNOWN" still has loaded=True and shows real numeric values, because the question is whether a file was read at all, not whether PURPLE was confident.

write_html(inputs, output_dir) lines 319–324 Render

A thin wrapper around render_html: creates the output directory if needed, writes the rendered string to {output_dir}/{sample_id}.igv.bars.html, and returns the output Path for the caller to log.

main() lines 327–370 CLI

The argparse entry point: declares 9 optional arguments and 1 required argument (--sample), validates the combination of inputs, then wires all load_* functions into a PlotInputs dataclass and calls write_html.

Required

  • --sample — sample identifier string

Optional (9 args)

  • --purple_tar, --qc_report
  • --cnvkit_cnr, --cnvkit_call_cns, --cnvkit_genemetrics
  • --msi_report, --locus, --output_dir

Hard validation: if both --purple_tar and --cnvkit_cnr are absent, ap.error() exits with code 2 and a descriptive message. Using ap.error() rather than raising an exception means argparse's standard exit code 2 ("bad arguments") is emitted — the signal recognised by shell scripts and DNAnexus job wrappers to distinguish user errors from runtime failures.
